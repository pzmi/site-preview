# 0076. `release-check`: one archive layout, notices from `cargo about`, a smoke of the extracted binary

Date: 2026-10-13

## Status

Accepted (owner, 2026-10-14). Amended 2026-10-14 (checkpoint OPS-06 review): fixed notice sections for the Rust
standard library and musl, a corrected preface, stricter archive checks and a reproducible
archive; see "Amendment".

## Context

plan.md section 11 M5 requires that the **published archive binary** is tested on a clean
system, on four targets, and ADR 0043 requires third-party licence notices (with the MPL-2.0
text and a source location for four crates) in what is distributed. OPS-06's release workflow
runs on four native runners and needs one command that builds, packages and tests per target.

## Decision

- `cargo xtask release-check [--target T]` builds `--release --locked -p preview-cli --target T`
  (default: the host), writes `target/release-check/T/site-preview-T.tar.gz` with one top
  directory `site-preview-T/` holding `site-preview`, `README.md`, `LICENSE-MIT`,
  `LICENSE-APACHE` and `THIRD-PARTY-NOTICES`, extracts it into a fresh temporary directory and
  tests only the extracted binary. The four release targets are the plan's; any other triple
  is accepted for a smoke run and flagged. A missing Rust target or `cargo-about` fails with
  the command that fixes it, never a skip.
- The smoke runs the binary with an empty environment except `PATH=/usr/bin:/bin`, after
  asserting `cargo`, `node` and `npm` are not in those directories. It checks `--version`,
  serves a copy of `tests/fixtures/site` on `--port 0`, requires `GET /` to be HTML carrying the
  reload client, edits `index.html` until a `reload` event arrives, sends SIGTERM by PID and
  requires exit 0, then requires the served tree to equal the fixture plus exactly that edit.
  The spawned server is killed by PID on every failure path; its logs are kept in
  `target/release-check/T/logs/`.
- `THIRD-PARTY-NOTICES` is generated by `cargo about` 0.9.2 (pinned in `tools/versions.toml`,
  installed with its `cli` feature) from the committed `about.toml` and `about.hbs`:
  `--locked --offline`, the dependency graph of `preview-cli` for the target, without
  dev- and build-only dependencies, licences limited to the set `deny.toml` admits. Each
  licence section lists its crates (`* name version crates.io-address`) and the licence text as
  the crates ship it (copyright notices included). A fixed preface gives the MPL-2.0 notice
  for `cssparser`, `cssparser-macros`, `dtoa-short` and `selectors`, with where their
  unmodified source is available.
- `release-check` fails when the archived notices differ from a fresh `cargo about` run, when a
  crate of `cargo tree -e normal --target T` (workspace members excluded) has no entry, and
  when a shipped MPL-2.0 crate lacks the licence text or its source address.
- The `artifact-smoke` CI job runs `release-check --target x86_64-unknown-linux-musl`, replacing
  its inline script. `release-check` stays out of `check` (a release build is slow); the catalog
  row keeps `in_check = false`.

## Consequences

- `cargo-about` joins the pinned tools; `tempfile` becomes a normal dependency of `xtask`
  (fresh extraction directory, removed on every exit path).
- `cargo about` lists proc-macro crates (normal dependencies in Cargo's graph) though they are not
  linked into the binary: the notices over-list rather than under-list.
- The first-party licence group has an empty "Used by" list (the workspace's own publishable
  crate is skipped in the template); the licence file text still appears.
- A new dependency under a licence outside `about.toml`'s `accepted` list fails the generator, in
  addition to `cargo deny`.
- The archive has a top directory; OPS-07's install command extracts with `--strip-components=1`.

## Amendment (2026-10-14): what `cargo about` cannot see, and a reproducible archive

The checkpoint review found that `THIRD-PARTY-NOTICES` covered only Cargo's graph: it omitted
the Rust standard library, which the compiler builds into every binary, and musl libc, which is
linked statically into the `*-linux-musl` binaries and whose MIT licence requires its notice in
every copy. It also found the MPL-2.0 preface naming the Servo repositories as the source of all
four crates, which is wrong (`dtoa-short` is not a Servo project).

- **Fixed sections.** `release-check` appends two committed texts after `cargo about`'s output:
  `tools/notices/rust-std.txt` (every target: the Rust Project's copyright, the dual licence,
  the MIT text verbatim from rust-lang/rust 1.97.0, the Apache-2.0 text being `LICENSE-APACHE`
  of the archive, the LLVM-exception parts, and where the per-component list is) and
  `tools/notices/musl-libc.txt` (`*-linux-musl`: musl 1.2.5's `COPYRIGHT`, unchanged, with its
  source address). The musl version is the one the Rust target ships; a toolchain that moves to
  another musl changes the heading and the text together. Both are in the generated file, so
  the "archived equals fresh" check covers them, and `release-check` fails when a section the
  target needs (or musl's copyright line) is missing.
- **Preface.** The MPL-2.0 source sentence names only the crates.io address on each entry line
  (each crate's own repository is linked from there); "linked into" is now "built into".
- **Entries.** An entry is exactly `* <name> <version> https://crates.io/crates/<name>/<version>`;
  other lines that start with `* ` are not counted.
- **Logs.** The stderr of `cargo fetch` and `cargo about` goes to `logs/notices*.log`.
- **Archive.** Reproducible and checked before extraction, as in ADR 0078's amendment.
